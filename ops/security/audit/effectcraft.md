The workspace has no network-capable crates at all (Cargo.lock has no ureq/reqwest/hyper/rustls/openssl/mio/socket2; `tokio` appears only via `wasm-bindgen-futures`). - The only code paths that touch the network are: a loopback-only JSON-lines control server (opt-in, `--control <port>`), a loopback-only bridge client, an opt-in model download that shells out to system `curl` for two fixed URLs with SHA-256 + size verification, `xtask web --serve` (dev tool, loopback), and script `Socket` (off by default). - `.mcp.json` registers two project-scoped MCP servers, both `cargo run --quiet --release -p effectcraft-cli -- mcp ...` (`--demo` headless, and `--bridge 9877`). The rev exists in the local filmcraft clone but only on `origin/effectcraft/webm-alpha`, not on filmcraft `main` (EFFECT-03). - Two of the four "build.rs" files are ordinary modules (`crates/pdf/src/build.rs`, `crates/project/src/build.rs`: `mod build;`). The real build scripts (`apps/effectcraft/build.rs`, `crates/ui-egui/build.rs`) are benign. `crates/model/tests/fixtures/cube.obj` is a 536-byte Wavefront OBJ text file, not an object file.

## Findings

**EFFECT-01 · MEDIUM · Agent capability (MCP/control) · `crates/engine/src/commands/settings.rs:255`, `crates/engine/src/prefs.rs:257`, `crates/script/src/runtime.rs:291`, `crates/script/src/socket.rs:22`, `crates/engine/src/commands/app_more.rs:178-198`**
Evidence: `cmd!("prefs.set", "Change Setting", [], None, "{key, value, values?: {key: value}}", always, prefs_set)`; `allow_scripts_write_files: bool = false`; `check_access` returns early `if s.prefs.scripting.allow_scripts_write_files`; `execute_file` doc: "(`confirmed: true` skips the question)". The `run_script` MCP tool description says "File access is limited to the project folder unless the user allows scripts to write files", but `execute_command {"command":"prefs.set","params":{"key":"scripting.allowScriptsWriteFiles","value":true}}` has no guard. After that, `run_script` can read any file the user can read, write/delete any file, open outbound TCP connections to any host, and call `File.execute` which opens a file with the OS default handler (confirmation can be skipped with `confirmed:true` through `execute_command file.executeFile`). In bridge mode `prefs.set` calls `save_prefs()` so the permissive setting persists in `%APPDATA%\EffectCraft\prefs.json`; in headless mode the session has no config store so it stays in memory.
Assessment: a legitimate-by-design capability for an automation tool, but the "Allow Scripts to Write Files and Access Network" gate gives no protection against a prompt-injected agent. Realistic exposure: an untrusted `.ecproj`, footage metadata, layer names or text (returned by `get_project`/`get_comp`) containing instructions to the agent. Not malicious.
Recommendation: in Claude Code do not auto-approve `execute_command`, `run_script`, `batch`, `control`, `open_project`, `save_project`, `render_frame` (it writes to a caller-chosen `path`); open only projects you trust while an agent is attached; consider asking upstream to make `prefs.set` refuse the `scripting.*` keys from the automation channels.

**EFFECT-02 · MEDIUM · Unauthenticated control channel · `apps/effectcraft/src/control_server.rs:27`, `docs/control-protocol.md:23`**
Evidence: `TcpListener::bind(("127.0.0.1", port))`; docs: "The port has no authentication, so only enable it while you use it." Opt-in only (`--control`), loopback only. Any local process, or another user on a multi-user Windows host, can send `engine.execute` / `ui.*` / `app.quit` and (with EFFECT-01) reach file read/write. Browser pages cannot: an HTTP or WebSocket request's first line is not a JSON object, so the server answers once and closes before any body is parsed. Hardened by external contributor Luskish in 2fc7da7 (read; it is the code now at HEAD).
Recommendation: launch the GUI with `--control <port>` only while driving it with the agent; prefer headless MCP (no listening socket) when the live window is not needed; pick a non-default port if other local users exist.

**EFFECT-04 · LOW · Model download via external `curl` · `crates/engine/src/models.rs:365`**
Evidence: `std::process::Command::new("curl").args(["-fsSL", "--retry", "2", "--connect-timeout", "20", "-o"]).arg(&tmp).arg(m.url)`. URL is a compile-time constant from the registry; result is read back and rejected unless `bytes.len() == m.size` and `sha256 == m.sha256` (`models.rs:256`). Acceptable; install nothing unless you want Roto Brush 2.0 / face tracking.

## Agent and MCP surface review
**Launch / transport.** The MCP server is `effectcraft-cli mcp [--demo | --project F.ecproj | --empty] [--autosave] [--gpu] [--bridge PORT]`: JSON-RPC 2.0 over stdio only (protocol versions 2025-06-18, 2025-03-26, 2024-11-05), hand-rolled in `crates/automation/src/server.rs`, no listener, no HTTP, so Origin/Host/DNS-rebinding checks are not applicable. Headless mode owns an in-process engine session. `--bridge PORT` forwards to the running GUI's control channel (`effectcraft.exe --control PORT`, `127.0.0.1` only; `BridgeClient::new` rejects non-loopback hosts). The repo's `.mcp.json` registers `effectcraft` (`cargo run --quiet --release -p effectcraft-cli -- mcp --demo`) and `effectcraft-app` (`... mcp --bridge 9877`).

**Tools (31; 22 headless + 9 bridge-only):** list_commands, describe_command, execute_command, run_script, get_project, get_comp, get_layer, get_property, set_property, add_keyframe, add_effect, list_effects, list_fonts, get_state, render_frame, open_project, save_project, undo, redo, history, script_ui, batch; bridge-only: screenshot, ui_inspect, ui_elements, ui_click, ui_drag, ui_key, ui_type, ui_set, control.

**Poisoning check.** I read every `name`, `description` and schema in `crates/automation/src/tools.rs` plus the `initialize` instructions in `server.rs`. They are purely functional (examples of JSON params, behavior notes). No hidden instructions, no `<IMPORTANT>` blocks, no requests to read files, call other tools or send data. Sweeps of the whole repo for injection phrases and for bidi/zero-width characters found nothing.

**Capability risks (design, not hidden):**
- `execute_command` / `batch` run any of ~hundreds of engine commands, including `file.open`, `file.saveAs`, `file.import`, `prefs.set`, `file.executeFile`, `edit.editOriginal`, render-queue and watch-folder commands, and `effect.plugins.load {path}` (loads an arbitrary `.wasm`; sandboxed with no imports, 1 GiB memory cap and fuel limit). Paths are arbitrary (no project-folder confinement) for open/save/import/render.
- `render_frame {path}` and `screenshot {path}` write a PNG to any caller-chosen path; `save_project {path}` writes `.ecproj` anywhere; `open_project {path}` and `screenshot` read back files. `screenshot`/`ui.screenshot` capture only the app's own viewport (egui `ViewportCommand::Screenshot`), not the desktop.
- `run_script` runs JavaScript (boa engine) in an After Effects-style object model. Default sandbox: file reads only under the project folder, no writes, no sockets, no `File.execute`. EFFECT-01 shows the agent can lift that itself.
- Expressions (`set_property {expression}`, project-embedded) run in a separate boa runtime with only compute natives (`__h` host query, wiggle, noise, random); no file/net/process access. Projects are JSON (`.ecproj`); a project file does not embed or auto-run application scripts, and installed scripts in `<config>\Scripts` run only when chosen by name. No auto-run on open.
- Indirect prompt injection: layer names, text layers, comments, expression text, marker comments and file names from an untrusted project are returned verbatim to the agent by `get_project`/`get_comp`/`get_layer`; nothing sanitizes them.
- `--autosave` writes checkpoints under `%APPDATA%\EffectCraft\EffectCraft Auto-Save\MCP\<pid>-<stamp>-<n>\` (or the custom Auto-Save folder); added by external contributor jonassneu (9d9f8ec), read: confined to that folder, `session.json` read-back is size-bounded.

## Setup facts (for the install and build scripts)
- **Cargo package and binary names:** GUI app: package `effectcraft` (`apps/effectcraft`), binary `effectcraft` (`effectcraft.exe`, GUI subsystem). CLI + MCP server: package `effectcraft-cli` (`apps/effectcraft-cli`), binary `effectcraft-cli` (`effectcraft-cli.exe`, console). The MCP server is a subcommand of the CLI (`effectcraft-cli mcp`), not a separate binary. Others: `xtask` (dev only), `effectcraft-web` (browser/wasm, not needed). Version 0.6.0, Rust 1.95+ (edition 2024), no pinned toolchain file.
- **Recommended Windows release build (MSVC):** `cargo build --release --locked -p effectcraft -p effectcraft-cli` (what `packaging/windows/package.ps1` runs, plus `--target x86_64-pc-windows-msvc` and `CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_RUSTFLAGS=-C target-feature=+crt-static`). Outputs: `target\release\effectcraft.exe` and `target\release\effectcraft-cli.exe` (or `target\x86_64-pc-windows-msvc\release\` when `--target` is given). Do not use `packaging/windows/package.ps1` unless you want the MSI (needs WiX 5.0.2); it skips signing when no secrets are set. First build fetches crates.io and `github.com/storytold/filmcraft` (network needed once; `--locked` keeps Cargo.lock).
- **Launch the GUI:** `effectcraft.exe [--control <port>] [--demo|--empty|--home] [project.ecproj | media files...]`; `--version`; env `EFFECTCRAFT_CONTROL_PORT` is the same as `--control`; `WGPU_BACKEND` overrides the graphics backend. With `--control` the window opens without taking focus and skips crash recovery. Data/config: `%APPDATA%\EffectCraft` (override `EFFECTCRAFT_CONFIG_DIR`): `prefs.json`, `shortcuts.json`, `models\`, `Scripts\`, `Plug-ins\`, `EffectCraft Auto-Save\`, `launch-pending` marker; disk cache `%LOCALAPPDATA%\EffectCraft\Disk Cache`; optional log file only when logging is enabled.
- **MCP server:** headless (no window, nothing listening): `target\release\effectcraft-cli.exe mcp [--demo | --project F.ecproj] [--autosave] [--gpu]` (default is an empty project; `--autosave` preserves unsaved work under the config dir; `--gpu` attaches a GPU adapter, otherwise CPU rendering). Live app: start `effectcraft.exe --control 9877`, then `effectcraft-cli.exe mcp --bridge 9877` (adds `screenshot` and `ui_*`/`control` tools; drives the running GUI over the loopback control channel). Transport is stdio. Register with Claude Code against the built exe instead of the repo's `cargo run` entries, e.g. `claude mcp add effectcraft -- D:\path\effectcraft\target\release\effectcraft-cli.exe mcp --autosave` and `claude mcp add effectcraft-app -- D:\path\effectcraft\target\release\effectcraft-cli.exe mcp --bridge 9877`. The shipped `.mcp.json` entries (`cargo run --quiet --release -p effectcraft-cli -- mcp --demo` / `-- mcp --bridge 9877`) rebuild on first use and can hit MCP startup timeouts; `docs/agents.md` advises building once first.
- **Native build prerequisites on Windows:** Rust MSVC toolchain 1.95+ (Visual Studio Build Tools with the "Desktop development with C++" workload, which also supplies the Windows SDK `rc.exe` used by `winresource`; without it the exe still builds but has no icon/version info unless `EFFECTCRAFT_REQUIRE_WINRES=1`). No cmake/nasm/clang/LLVM needed on Windows: the `-sys` crates in the lock are `alsa-sys` (Linux), `wayland-sys`, `glutin_*`, `windows-sys`, `core-foundation-sys`, `objc-sys`, `renderdoc-sys`, none requiring external C libraries on Windows. A GPU with DirectX 12/Vulkan (wgpu) is used when available, else CPU/OpenGL fallback. ffmpeg is NOT required (only tests use it). `curl.exe` (ships with Windows 10+) is needed only for the optional model download.
- **Linux build packages** (from `release.yml:179-182`, apt): `libxkbcommon-dev libwayland-dev libx11-dev libxrandr-dev libxi-dev libgl1-mesa-dev libasound2-dev` (plus `pkg-config`, a C compiler); packaging extras: `desktop-file-utils appstream python3-yaml zsync`. FreeBSD pkgs: `git curl pkgconf cmake python3 libxkbcommon wayland libX11 libXcursor libXrandr libXi libxcb mesa-libs vulkan-loader gtk3 fontconfig freetype2 alsa-lib`.
- **Other things a Windows user must know:** (1) nothing runs at startup or install beyond the optional MSI; the app has no auto-update or telemetry. (2) Audio uses `cpal` output only (alsa-sys is Linux-only), no microphone access. (3) Windows spawns a hidden `powershell.exe` every 30 s for a memory readout (EFFECT-05). (4) Keep the "Allow Scripts to Write Files and Access Network" setting off and do not auto-approve `execute_command`/`run_script` tools (EFFECT-01). (5) Running `cargo run`/`cargo build` executes build scripts and proc-macros of all dependencies, so build only after approving the `--locked` lockfile at this commit.
