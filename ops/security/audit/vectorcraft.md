## Summary

- **No network egress at all in the shipped app.** No HTTP/WebSocket client crate in `Cargo.lock` (574 packages, all `registry+crates.io` with checksums, no `[patch]`/`git`/alt registry), no telemetry/analytics/update-check/crash-upload code, no `fetch`/`XMLHttpRequest` in the web build. The only listener is the opt-in control server on `127.0.0.1`; the only outbound is the opt-in MCP client to a loopback address and browser launches on explicit user clicks (Help links, Attributes "Open URL").
- **Control channel (`--control <port>`, off by default):** loopback only, JSON-lines, **no authentication** (documented), but it actively rejects HTTP so a web page (CSRF / DNS rebinding) cannot execute commands (hardened 2026-10-06 by external contributor Luskish, 339eb78a, with tests). Any local process or other local user can still drive it.
- **MCP server (`vectorcraft-cli mcp`, stdio):** 25 tools, descriptions/schemas read in full, **no tool poisoning or injection text**. Capability is broad: `run_command` reaches every engine command; `open_file`, `save_file`, `export`, `screenshot` take arbitrary filesystem paths; `export {format:"txt"}` writes caller-controlled text to any filename (so an agent steered by a malicious document could drop e.g. a `.bat` in the Startup folder). This is by-design automation capability, but matters for an owner who will run agents against untrusted files.
- **Printing (`printing.rs`) spawns PowerShell** on Windows (`powershell -NoProfile -NonInteractive -Command`); the user-supplied `printer` name is quoted with a helper that only doubles ASCII `'`, while PowerShell also treats U+2018/2019/201A/201B as quote characters, so a crafted `printer` param to `file.print` looks injectable (speculation: not run). Reachable only via control channel / MCP `run_command`.
- **Import (SVG/AI/PDF/EPS/Affinity/DXF):** all in-process pure Rust. No Ghostscript or any interpreter, no script execution, no remote fetch of `href`s or fonts (remote hrefs become a placeholder; `@font-face`/`@import` ignored). Local `file://`/absolute `<image href>` paths **are read** (local-only; images become linked images). The EPS PostScript interpreter refuses `file`, `deletefile`, `renamefile`, `run`.
- **Build-time code is benign:** 3 real Cargo build scripts (icon/version resource, optional local font embedding, contributor-credits table), no proc-macro workspace crates, `.cargo/config.toml` is only an `xtask` alias, `xtask` downloads only on explicit opt-in subcommands (sha256-pinned for Affinity corpus).
- **`vendor/windows-link`** is upstream `windows-link` 0.2.1 with one documented macro arm for the Windows 7 build, applied only by `packaging/windows/windows7.ps1` via `--config patch...`. Its first version (njmueller, 58e3916e) put a workspace-wide `[patch.crates-io]` and dropped the lockfile checksum; the maintainer corrected that the next day (caeecf4b). The one scanner HIGH (`windows-registry = "0.6"`) is a false positive: it is Microsoft's registry crate, used read-only to list fonts registered under `HKLM/HKCU\Software\Microsoft\Windows NT\CurrentVersion\Fonts`.
- Repo is 10 days old (first commit 2026-09-30), 1303 commits, ~90% by two maintainer identities (bflatastic/BFlat) plus Brandon Thomas, heavily AI-assisted. No external-contributor commit looked malicious.

## Findings

**VECT-01 · MEDIUM · Agent capability / arbitrary file access · `crates/mcp/src/tools.rs:247-300`, `crates/ui-egui/src/control.rs:130-340`, `crates/engine/src/cmd/fileio/mod.rs:681-690`**
Evidence: tool `export`: "`path`: Destination file (omit to get dataBase64)" with `"format"` enum including `txt`; `writable_format` returns `(Some(f), _) => format(f)` so an explicit `format` ignores the path's extension; `screenshot` does `std::fs::write(path, png)`; `open_file` "File path"; `run_command` "Execute any VectorCraft command by id".
Assessment: Any MCP client (or control-channel client) can read/parse any local file the user can read (`open_file`, `document.open`), overwrite any file with PNG data (`screenshot {path}`), and write attacker-chosen text content to an arbitrary filename/extension (`export {format:"txt", path:"...\\Startup\\x.bat"}` writes the document's text objects verbatim; speculation that this yields login-time code execution, not run). Also reachable: `links.editOriginal` (shell-open any linked path), `attributes.openUrl` (open any URL/scheme), `file.print`, `plugin.install` (wasm, sandboxed), `prefs.set`. No path allowlist, no confirmation. This is the intended "agent drives the app" capability, but a prompt-injection in an opened document (text/layer names come back to the agent via `inspect_document` and `vectorcraft://object/{id}` resources) can steer an agent into these.
Recommendation: Only register the MCP server for sessions where you trust the documents; prefer `--headless` with a scratch working directory for untrusted files; consider asking upstream for a path allowlist/confirmation for write tools and for `format` to be checked against the path extension.

**VECT-02 · MEDIUM (speculative exploitability) · Command injection · `apps/vectorcraft/src/printing.rs:97-99,166-176`**
Evidence: `fn ps_quote(s: &str) -> String { format!("'{}'", s.replace('\'', "''")) }` and `Start-Process -FilePath {path} -Verb PrintTo -ArgumentList {ps_quote(&format!("\"{}\"", p.replace('"', "")))} -WindowStyle Hidden` run via `powershell -NoProfile -NonInteractive -Command <script>`. `p` is `job.printer` = `s("printer")` from `file.print` params (`crates/ui-egui/src/print.rs:89`).
Assessment: PowerShell treats U+2018, U+2019, U+201A and U+201B as single-quote characters (a lone one closes the string); only ASCII `'` is doubled here, so a `printer` value like `x’; <cmd>; ‘` appears to break out of the quoted argument. Needs control-channel/MCP access to supply `printer` (not reachable from a document alone; the GUI printer list comes from WMI). Same trust boundary as VECT-01 but gives direct process execution. Not run, label: speculation.
Recommendation: Report upstream; fix is to pass the printer via an environment variable or `-File`/`-ArgumentList` array and reject names containing non-ASCII quote characters.

**VECT-03 · LOW · Shell-open of document-supplied paths/URLs · `apps/vectorcraft/src/main.rs:339-354`, `crates/ui-egui/src/io.rs:555`, `crates/ui-egui/src/panels/links.rs:175-192`, `crates/ui-egui/src/panels/attributes.rs:163-170`, `apps/vectorcraft/src/main.rs:325-327`**
Evidence: `explorer "<path>"` (Edit Original / Show Package) with no extension filter; `webbrowser::open(url)` for `attributes.openUrl {url}`.
Assessment: A linked-image path comes from the file (SVG `<image href>` placeholders keep the href as the link path, `crates/svg/src/import/files.rs:131-141`; `.vectorcraft`/`.ai` links). If a document links to an existing executable and the user (or an agent via `links.editOriginal`) triggers Edit Original, Explorer opens/launches that file. `webbrowser` scheme filtering not verified offline (speculation). Requires an explicit action, hence LOW.
Recommendation: Do not use "Edit Original"/"Open URL" on untrusted documents.

**VECT-04 · LOW · Local file read from SVG import · `crates/svg/src/import/files.rs:89-110,121-147`**
Evidence: `target()` maps `file://...` and absolute/relative hrefs to local paths read through `opts.read` (`std::fs::read`, `apps/vectorcraft/src/main.rs:314`); `None if h.contains("://") => return (h, false)` for remote URLs, which become placeholders.
Assessment: Opening an SVG whose `<image href="file:///C:/Users/x/secret.png">` embeds that local image into the document as a linked raster (only if it decodes as an image or SVG). No network, so no exfiltration unless the user then shares/exports the result; no tracking-beacon behaviour (no remote hrefs or fonts are fetched; `<script>` is never executed, `@font-face`/`@import` blocks are skipped, text uses local fonts).
Recommendation: Informational; avoid sharing exports of untrusted SVGs without checking.

**VECT-05 · LOW · Unauthenticated loopback control · `apps/vectorcraft/src/control_server.rs:26-38`, `docs/control-protocol.md:3-13`**
Evidence: "listens on `127.0.0.1:<port>` (loopback only)... The port has no authentication".
Assessment: Browser CSRF/DNS-rebinding is blocked by design (first line must be a JSON object with `method`; HTTP request lines get one error reply and the connection is closed; test `http_request_closes_before_the_body_runs`). Before 339eb78a (2026-10-06) the server did not close on HTTP, so a cross-origin text/plain POST body could have executed commands; this is fixed at HEAD. Residual: any local process, or another local user on a shared machine, can drive the app as you. Opt-in only.
Recommendation: Use `--control` only while needed; pick a non-default port.

**VECT-06 · LOW · Executable resolution by bare name · `apps/vectorcraft/src/printing.rs:153,182,188`, `apps/vectorcraft/src/main.rs:271,343`**
Evidence: `Command::new("powershell")`, `Command::new("explorer")`, `Command::new("control.exe")` (contrast `reg.exe` in `i18n/mod.rs:316`, which uses `%SystemRoot%\System32` explicitly "so nothing named reg in the app's folder or on PATH runs instead").
Assessment: Rust's Windows resolution searches the application directory before System32. Only matters if the install/portable directory is writable by an attacker. Hygiene.

## Agent and MCP surface review

- **Launch and transport:** `vectorcraft-cli mcp [--connect ADDR | --headless]` speaks newline-delimited JSON-RPC 2.0 on stdio (protocol revision 2025-06-18; no HTTP/SSE; logs to stderr; `logging/setLevel` optional). No flag: tries `127.0.0.1:7979`, silently falls back to headless. `--connect` drives the running GUI through the control channel; `--headless` is an in-process engine with a CPU renderer. Control server: `vectorcraft --control <port>` (or env `VECTORCRAFT_CONTROL_PORT`), `127.0.0.1` only, no auth, HTTP rejected.
- **Registration with Claude Code (docs/mcp.md:21-30):** `claude mcp add vectorcraft -- "<abs path>\target\release\vectorcraft-cli.exe" mcp` (also `-vectorcraft-headless ... mcp --headless`, `vectorcraft-app ... mcp --connect 127.0.0.1:7979`), or `{"mcpServers": {"vectorcraft": {"command": "...", "args": ["mcp"]}}}`.
- **Tools (25, verbatim names):** `list_commands`, `run_command`, `inspect_document`, `inspect_ui`, `select_tool`, `pointer_gesture`, `draw_path`, `draw_shape`, `set_paint`, `press_key`, `type_text`, `invoke_menu`, `open_panel`, `screenshot`, `open_file`, `save_file`, `export`, `add_text`, `apply_effect`, `pathfinder`, `transform`, `create_graph`, `text_wrap`, `undo`, `redo`. All carry `openWorldHint:false`; read-only hints set only on `list_commands`, `inspect_*`, `screenshot`. Server `INSTRUCTIONS`, 5 prompts (`poster`, `icon-set`, `recolor`, `trace-and-style`, `export-set`; read in full: design workflows, no hidden instructions) and resource templates (`vectorcraft://object/{id}`, `command/{id}`, `effect/{id}`, `swatch/{name}`) were read; **no poisoning, no `<IMPORTANT>` blocks, no instructions to read files, call other tools or send data**. Injection-phrase sweep over the whole repo (md, rs, toml, json, yml, svg, tsv, examples) found only benign hits ("without asking" UI strings, curl in CI).
- **Capability risks:** see VECT-01/02/03/05. Tool results include document-derived strings (layer names, text content, file names), an indirect prompt-injection channel inherent to any document-editing MCP server. `screenshot {window:true}` captures only the app's own egui window (no OS screen capture API anywhere in the repo). No tool exposes shell execution directly.
- **Plugin sandbox (`crates/plugins`):** wasmi interpreter, `#![forbid(unsafe_code)]`, modules with **any import are rejected** (no WASI, files, network, clock, randomness), fuel budget, 60 s wall-clock, 512 MiB memory cap, strict `EnforcedLimits`, fresh instance per run, 32 MiB module cap. Installed explicitly (`plugin.install {path|dataBase64}`, File > Open of `.wasm`, or the "Additional Plug-ins Folder" preference); **no auto-download**. Plugins can only transform the selected objects' JSON. `desaturate.wasm`: walked the section table by hand: sections type/function/table/memory/global/export/element/code/data only, **no import section, no custom sections**; exports `vc_abi_version`, `vc_alloc`, `vc_manifest`, `vc_run`, `memory`; manifest id `org.vectorcraft.example.desaturate`; built from `crates/plugins/example` (commit 811ad1ef, bflatastic). Not a risk.

## Setup facts (for the install and build scripts)

- **Cargo package and binary names:** GUI app: package `vectorcraft` -> `vectorcraft.exe` (default-run). CLI + MCP server (same binary): package `vectorcraft-cli` -> `vectorcraft-cli.exe`. Web: package `vectorcraft-web` (wasm; `cd apps/vectorcraft-web && trunk build --release`, not needed on Windows desktop). Dev tool: package `xtask` (`cargo xtask ...`, do not run).
- **Recommended Windows release build:** `cargo build --release --locked -p vectorcraft -p vectorcraft-cli` (exactly what `packaging/windows/package.ps1` runs, with `--target x86_64-pc-windows-msvc` optional on x64). Outputs `target\release\vectorcraft.exe` and `target\release\vectorcraft-cli.exe`. Optional `$env:VECTORCRAFT_REQUIRE_WINRES = '1'` to make a missing resource compiler a hard error (otherwise it only warns and the exe has no icon/version info). Do not use `cargo xtask ci`. Optional: `$env:CRAFT_FONTS_DIR = '<abs path to storytold/craft-fonts checkout>'` embeds Japanese fonts (not required; without it Japanese text uses installed system fonts). The Windows 7 build (`packaging/windows/windows7.ps1`) is experimental and unnecessary on Windows 10/11.
- **Toolchain:** stable Rust with `rust-version = 1.95`, edition 2024 (no `rust-toolchain` file; use latest stable via rustup).
- **How to launch the GUI:** `target\release\vectorcraft.exe [file.svg|file.vectorcraft|...]`. Enable the automation channel only when needed: `vectorcraft.exe --control 7979` (or env `VECTORCRAFT_CONTROL_PORT=7979`); other flags/env: `--in-window-menus`/`VECTORCRAFT_IN_WINDOW_MENUS`, `--version`, `VECTORCRAFT_NO_PREFS=1` (neither read nor write prefs), `WGPU_BACKEND`, `WGPU_ADAPTER_NAME`, `WGPU_POWER_PREF`, `RUST_LOG`. Renderer is wgpu (DX12/Vulkan on Windows); needs a working GPU driver (it retries on another adapter on failure). Data and config: `%APPDATA%\VectorCraft\ui.json` (preferences, also reads legacy `%APPDATA%\DrawCraft`), logs in `%APPDATA%\VectorCraft\logs\vectorcraft.log` (5 rotated files), `%APPDATA%\VectorCraft\Data Recovery`; print jobs in `%TEMP%\vectorcraft-print` (removed after an hour). The control server logs `vectorcraft: control server listening on 127.0.0.1:<port>` to stderr/log.
- **How to launch the MCP server:** `vectorcraft-cli.exe mcp [--connect 127.0.0.1:<port> | --headless]`, transport **stdio** (JSON-RPC 2.0, protocol 2025-06-18). `--connect` drives the running GUI through its control channel (start `vectorcraft.exe --control <port>` first); `--headless` is a self-contained in-process engine (CPU renderer; no `inspect_ui`, `type_text`, `open_panel`, `screenshot {window:true}`); with no flag it tries `127.0.0.1:7979` and silently falls back to headless. Register with Claude Code: `claude mcp add vectorcraft -- "C:\path\to\target\release\vectorcraft-cli.exe" mcp --headless` (safest default) or `... mcp --connect 127.0.0.1:7981` for the live GUI. Recommendation: pick a port other than 7979 for each ArtCraft app (CLAUDE.md states sibling apps default to 7979, so an unflagged `mcp` could attach to the wrong app) and always pass an explicit `--connect`/`--headless`.
- **Other CLI uses (no GUI):** `vectorcraft-cli.exe run --in FILE --cmd ID --export out.pdf`, `convert IN OUT`, `info FILE`, `commands`, `bench`, `perf`.
- **Native build prerequisites on Windows:** Visual Studio 2022 Build Tools with "Desktop development with C++" (MSVC x64 linker) and a Windows 10/11 SDK (the SDK `rc.exe` is used by `winresource` for the exe icon/version). No cmake, nasm or clang/LLVM needed (pure-Rust renderer/codecs/wasmi; the only `-sys` crates in the lock are platform bindings: windows-sys, wayland-sys, objc-sys, core-foundation-sys, glutin_*_sys, renderdoc-sys, jni/ndk-sys). Git is only needed for `xtask`/`package.ps1` build-SHA lookup. For an MSI: `dotnet tool install --global wix --version 5.0.2` (not needed to just run the exe).
- **Linux build packages (from `release.yml` apt line, Ubuntu 22.04):** `libxkbcommon-dev libwayland-dev libx11-dev libxrandr-dev libxi-dev libgl1-mesa-dev`; packaging additionally `desktop-file-utils appstream python3-yaml zsync` and nfpm. FreeBSD (`pkg install`): `bash curl git pkgconf cmake python3 libxkbcommon wayland libX11 libXcursor libXrandr libXi libxcb mesa-libs vulkan-loader gtk3 fontconfig freetype2 alsa-lib`. macOS: Xcode command-line tools (`cargo xtask bundle` makes `dist/VectorCraft.app`).
- **Anything else a Windows user must know:** (1) first build compiles ~574 crates with `lto = "thin"`, `codegen-units = 1`; expect a long link step and several GB of target dir (CLAUDE.md warns of up to ~30 GB per agent target dir). (2) The app is local-only: no account, no network. (3) Printing on Windows shells out to PowerShell (`Get-CimInstance Win32_Printer`, `Start-Process -Verb Print`) and needs a PDF viewer registered for the print verb. (4) Because `Command::new("powershell"/"explorer")` resolves from the app directory first, keep the install folder non-writable by other users. (5) Keep `--control` off unless an agent is actively driving the app, and avoid agent sessions that open untrusted SVG/PDF/AI/EPS files while MCP write tools are available (VECT-01/02/03).
