## Summary
- **Speech crate (`filmcraft-speech`) is clean and inert in the default build.** The only network client in the repo (ureq + rustls + RustCrypto) is compiled only with the non-default feature `whisper` (apps) / `download` (crate). Nothing in `Cargo.toml`, CI or packaging enables it, so the Windows release command produces binaries with no HTTP client, no TLS and no candle.
- When enabled, the downloader fetches only OpenAI Whisper weights from `https://huggingface.co/openai/whisper-{tiny,base,small}/resolve/<40-hex git revision>/<file>`, each file checked against a hard-coded SHA-256 and size, only on an explicit `transcript.downloadModel` command (never at startup, never automatic). Transcription runs locally on CPU (candle). Audio is never uploaded; there are no API keys, tokens, or auth headers anywhere in the repo.
- **No telemetry, analytics, update checks, crash upload, fingerprinting, persistence, registry/startup changes, keyloggers, clipboard monitoring, desktop capture, process injection, or obfuscation found.** No secrets, no bidi/zero-width Unicode, no long base64 blobs, no PE/ELF/Mach-O/wasm files tracked (see FILM-07 for 14 stray `.h264` fixtures).
- **`.mcp.json` is benign**: two stdio servers that run the locally built `target/release/filmcraft-cli` (`mcp --bridge 127.0.0.1:9876` and `mcp --demo`). No remote servers, no env vars, no tokens. Only the path is attacker-relevant: a future PR that edits `.mcp.json` would be auto-offered to any agent that opens the repo, so diff it on every update.
- **Control channel is loopback-only but unauthenticated** (FILM-01); MCP is stdio only (no HTTP, no Origin/Host problem). MCP tool names/descriptions/schemas are clean (no poisoning), but `command_run` / `ui_control` are universal dispatchers that accept arbitrary filesystem paths (FILM-02).
- Build-time code is benign: 3 `build.rs` (icon resource on Windows; font embed from an optional local dir; contributor-credit tables baked from local JSON/TOML), no proc-macro crates, `.cargo/config.toml` has only an `xtask` alias, xtask is dev tooling (cargo/git/wasm-bindgen), no network.
- Supply chain: 694 lock packages, all registry crates.io with checksums (47 are workspace path crates), no git/patch/replace. External contributors' recent dependency additions are small and benign (`cpu-time` 1.0.0, `windows` bindings features, one new workspace crate `filmcraft-apv`, symphonia `aiff` feature).
- CI is sound: no `pull_request_target`, PR-triggered workflows are `contents: read` with no secrets, signing secrets only in an `environment: release` restricted to the `release` branch; some third-party actions unpinned (INFO).

## Findings
(Ordered by severity. No CRITICAL or HIGH findings.)

**FILM-01** · **MEDIUM** · Agent/automation attack surface · `apps/filmcraft/src/control_server.rs:27`, `docs/control-protocol.md` · evidence: `TcpListener::bind(("127.0.0.1", port))`; docs: "The port has no authentication, so only enable it while you use it." · The control server is off by default and loopback-only, and the 2026-10-06 hardening by external contributor Luskish (`023127e`, reviewed, matches its message) makes it reject any first line that is not a JSON object with a string `method` and close the connection. That blocks browser `fetch`/WebSocket cross-protocol and DNS-rebinding style attacks (an HTTP request line is rejected before its body is parsed; there is no HTTP server, so Origin/Host checks are moot and the test `http_request_closes_before_the_body_runs` covers it). Remaining risk: no token, so any local process, or any other local Windows user, can connect to the port and run any engine command (open/save/export to arbitrary paths, screenshots, key/mouse injection into the app, `app.quit`). Recommend: launch with `--control` only while driving the app, pick a high random port, do not run it on a shared machine; upstream should add a per-session token (e.g., generated, passed to `filmcraft-cli --bridge`).

**FILM-02** · **MEDIUM** · Agent-targeted / capability risk · `crates/automation/src/server.rs` (`command_run`, `command_batch`, `ui_control`, `media_import`) · evidence: `command_run` description "Run a command by id with JSON params", annotations `destructive_hint = true`; `ui_control`: "call any control-channel method directly" · Tools are poisoning-free (all names, descriptions, input-schema doc comments and the server `INSTRUCTIONS` string were read verbatim; nothing instructs the model to read files, hide actions, call other tools or send data). But the command registry behind `command_run` accepts arbitrary absolute paths with no allow-list or confirmation: write (`file.save/saveAs/saveCopy/exportMedia/exportFrame`, `lut.export`, `shortcuts.export`, `presets.export`, `export.presets.export`, `ui.screenshot {path}` which writes a PNG of the app window only), read/import (`file.open`, `file.import`, `media_import`, `lut.import`, `captions.import`, `shortcuts.import`), directory enumeration (`mediaBrowser.list/probe`), microphone capture (`audio.voiceover.start`/`stop`, which records to a file with only the OS permission gate), and downloads (`transcript.downloadModel` in a `whisper` build). Project text (clip names, markers, captions, transcripts, metadata) is returned to the agent by `doc_inspect`/`sequence_inspect`, so a hostile project file or media file is a prompt-injection vector that could steer an agent into those commands. Hints are honest (`command_run`, `command_batch`, `ui_control` marked destructive; read-only tools marked read-only), so a client that prompts on destructive tools will ask first. Recommend: keep `command_run`/`command_batch`/`ui_control` on "ask each time", do not auto-approve them, and open only trusted projects while an agent is attached.

**FILM-03** · **LOW** · Network / model download (speech) · `crates/speech/src/models.rs:224-271`, `crates/engine/src/transcript.rs:420-433` · evidence: `url: concat!("https://huggingface.co/openai/", $repo, "/resolve/", $rev, "/", $name), sha256: $sha` and `if sha != f.sha256 || got != f.size { remove_file(part); return Err(..checksum mismatch..) }` · Not automatic: `transcribe` returns `NotInstalled` if the model is missing (no implicit download; "Automatically transcribe clips" defaults to false). Only the 3 catalogue models can be requested (id looked up in a static table; the URL is never user-supplied). Residual notes: (a) the SHA-256 values and Hugging Face revision hashes are hard-coded and could not be cross-checked offline (tokenizer.json shares one hash across the 3 models as expected for OpenAI's multilingual tokenizer); (b) the body is hashed after streaming with no byte cap during download (a hostile server could fill disk before the check fails; HF is TLS-authenticated); (c) `installed()` re-checks only file size, not hash, on later loads; (d) `rustls-rustcrypto = 0.0.2-alpha` (unaudited alpha crypto provider) is used for TLS instead of ring/aws-lc, a hygiene concern only for builds that enable `whisper`; (e) a `.part` file is left behind on read errors; (f) the confirm dialog described in docs is a host convention, so an MCP/CLI client can invoke `transcript.downloadModel` without any prompt. Recommend: keep `whisper` off unless you want transcription; if wanted, build once with `--features whisper`, and cross-check the SHA-256 of `model.safetensors` for `whisper-base` (`07cadb9f25677c8d50df603e66a98fbd842cce45047139baeb16e6219a1e807b`) against Hugging Face.

**FILM-04** · **LOW** · Process execution · `apps/filmcraft/src/main.rs:219-246`, `crates/ui-egui/src/panels/menu_dialogs.rs:117-195`, `crates/engine/src/project_tools.rs:961` · evidence: `Command::new("explorer")` with `c.arg(path)`; `"edit.editOriginal"` opens each item's recorded file path · Windows: `explorer <path>` shell-opens whatever the project item's media path is (an `.exe`/`.bat`/`.lnk` would run; a UNC path would trigger SMB authentication, which would leak NTLM hashes, speculation for crafted projects). Path comes from a project file (`.fcproj`, EDL/AAF import) or `media.relink`, so opening an untrusted project and pressing Cmd+E (or an agent running `edit.editOriginal`) on a poisoned item is the trigger. No shell string interpolation (args are passed as argv). Expected Premiere-style feature; low practical risk. Recommend: do not use Edit Original on projects you did not create; upstream could restrict to known media extensions.

**FILM-05** · **LOW** · Microphone · `apps/filmcraft/src/audio_in.rs:44,101`, `crates/engine/src/voiceover.rs` · evidence: `h.default_input_device()`, `dev.build_input_stream(..)` · Only opened for Voice-Over recording (`audio.voiceover.start`), buffered in RAM (capped at 2^28 samples) and written into the project on stop. External contributor cirocueto2013-wq's `7151d32` (integer CPAL sample formats, error recovery) was reviewed: matches its message.

**FILM-06** · **LOW** · Supply chain / hygiene · `Cargo.lock` · 694 packages, 647 from crates.io with checksums, 47 workspace path crates, no git/registry-other sources, no `[patch]`/`[replace]`. Recommend keeping `--locked`.

## Agent and MCP surface review
- **Launch/transport**: MCP is `filmcraft-cli mcp ...` over **stdio only** (rmcp features `server, macros, transport-io`; no HTTP/SSE), spawned as a child process by the client. Modes: headless in-process session (`--demo`, `--project p.fcproj`, or empty) or `--bridge 127.0.0.1:9876` to the running GUI's control server. There is no listening MCP port, so no Origin/Host/DNS-rebinding exposure; the only listener is the optional control server (FILM-01). Non-JSON stdin lines get a JSON-RPC `-32700` parse error; unknown tool arguments are rejected.
- **Registration**: repo `.mcp.json` (committed once, `3eac0a2` Brandon Thomas 2026-09-30, never changed) registers `filmcraft` (`target/release/filmcraft-cli mcp --bridge 127.0.0.1:9876`) and `filmcraft-headless` (`target/release/filmcraft-cli mcp --demo`). Claude Code asks for approval of project-scoped servers on first use. The command is a relative path to a binary that only exists if you build it.
- **Tools (17)**: `command_list`, `command_run`, `command_batch`, `doc_inspect`, `render_preview`, `project_inspect`, `sequence_inspect`, `media_import`, `render_frame`, `ui_inspect`, `ui_elements`, `ui_click`, `ui_drag`, `ui_key`, `ui_type`, `ui_screenshot`, `ui_control`. Resources: `filmcraft://document`, `filmcraft://commands`. Descriptions are short, factual and match behavior (quoted examples: "List every command (id, label, menu path, shortcut, parameter doc, enabled now)", "Import media files by absolute path (MP4/MOV, WAV/MP3/FLAC/AIFF/Ogg, PNG/JPEG/…)", "Live app: call any control-channel method directly"). Server instructions string: "FilmCraft video editor (Premiere Pro-class). Every edit is an engine command: …". **No tool poisoning or hidden instructions found.**
- **Annotations**: every tool has title + 4 hints; `command_run`, `command_batch`, `ui_control`, and the UI input tools are non-read-only/destructive; `command_list`, inspectors, `render_*`, `ui_screenshot` are read-only (the screenshot tool writes a temp PNG `filmcraft-mcp-<pid>.png` in `%TEMP%` and deletes it after reading).
- **Capability risks**: see FILM-02 (arbitrary paths via `command_run`, mic capture via `audio.voiceover.*`, `edit.editOriginal` shell-open, model download in `whisper` builds). No tool executes arbitrary commands or opens arbitrary network connections; nothing inside the engine spawns a shell. `remove_partial` (cancelled export cleanup, `long_job.rs:125`) deletes only files named like the export output written since the job started.
- **Prompt-injection vector**: project/media text returned by inspect tools (see FILM-02).

## Setup facts (for the install and build scripts)
- **Cargo packages and binaries**: GUI app = package `filmcraft` (`apps/filmcraft`), binary `filmcraft` (`filmcraft.exe`; `default-run = "filmcraft"`; release Windows build uses `windows_subsystem = "windows"`, so no console output). CLI plus MCP server = package `filmcraft-cli` (`apps/filmcraft-cli`), binary `filmcraft-cli` (`filmcraft-cli.exe`); the MCP server is the `mcp` subcommand of this CLI (implementation crate `filmcraft-automation`), not a separate binary. Web build = package `filmcraft-web` (wasm, built with `cargo xtask web`; not needed on Windows desktop). `xtask` is dev tooling.
- **Recommended Windows release build** (matches `packaging/windows/package.ps1:65`): `cargo build --release --locked -p filmcraft -p filmcraft-cli` (optionally `--target x86_64-pc-windows-msvc`). Outputs: `target\release\filmcraft.exe`, `target\release\filmcraft-cli.exe`. Do NOT add `--features whisper` (pulls in candle, ureq, rustls, ring, model downloads). Optional, as CI does: set `CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_RUSTFLAGS=-C target-feature=+crt-static` (static CRT, no VC++ redistributable) and `FILMCRAFT_REQUIRE_WINRES=1` (fail if the icon/version resource cannot be embedded; otherwise only a warning). Toolchain: Rust stable >= 1.95 (edition 2024; no `rust-toolchain` file; install via rustup). Do not set `CRAFT_FONTS_DIR` unless you have reviewed `storytold/craft-fonts` (optional CJK fonts; CI pins `abb83316d96aa59c1cf64784289e378fe9fa5695`).
- **Launch the GUI**: `filmcraft.exe [--control <port>] [--demo | --empty] [--recover | --no-recover] [--data-dir <dir>] [project.fcproj | media files...]`; `--help`, `--version`. Env: `FILMCRAFT_CONTROL_PORT`, `FILMCRAFT_DATA_DIR`, `FILMCRAFT_CPU_COMPOSITE=1` (disable GPU compositor). Default start opens the demo project (`demo: true` unless `--empty`/Settings). With `--control` the window opens without taking keyboard focus. Data/config location: `%APPDATA%\FilmCraft` (auto-save and crash recovery sessions, `Logs\crash-<day>.log` and session logs, preferences, export presets, workspaces, `models\<id>\` for Whisper in a `whisper` build); `--data-dir`/`FILMCRAFT_DATA_DIR` overrides. Headless (no window; in-process engine): `filmcraft-cli.exe mcp --demo`, or `mcp --project C:\path\p.fcproj`, or `mcp` (empty project). Drives the running GUI: start `filmcraft.exe --control 9876`, then `filmcraft-cli.exe mcp --bridge 127.0.0.1:9876` (loopback addresses only; the bridge client refuses others).
